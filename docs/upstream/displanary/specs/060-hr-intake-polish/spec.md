# Feature Specification: HR intake polish

**Branch**: `060-hr-intake-polish` (from `main`) | **Created**: 2026-10-21 | **Status**: Approved

**Input**: Product owner tested the merged report → case flow (2026-10-21): attaching looks like "Word only" and there is no drag and drop; new reports are not the first thing HR sees; the reporter answered «عدنة بس مامعرف» ("we have it but I don't know") to the place question and it was stored as the place; the reporter gave a date but HR was asked for it again; reports and cases lack visible numbers; an unknown name blocked opening the case.
Decisions (2026-10-21): an unknown name is added as an employee on the same screen (quick-add); report numbers everywhere (R-0001), and the case number visible on the open-case screen, the case page and lists. Product principles from 059 apply (take facts from what people have, ask only what is missing, AI proposes and a human confirms, never block).

## Requirements
- **FR-001 Attach**: every attach control (reporter start step, chat composer, review screen; HR blank new case) accepts drag and drop of several files onto a visible drop area as well as the file picker. The picker lists every allowed type (email .eml/.msg, PDF, Word, photos, video for reporters), and the hint names them; a refused file says which types and sizes are allowed.
- **FR-002 New reports first for HR**: on HR's home ("My work"), new reports waiting in the inbox appear first in "Needs action", above case tasks, and the counters row gets a "New reports" card (count, links to the inbox). The top-bar inbox badge stays.
- **FR-003 "I don't know" is never a fact**: a reporter answer that expresses not knowing (e.g. «لا أعرف», «ما أعرف», «مامعرف», «ما ادري», «ماكو فكرة», «عدنة بس مامعرف», "I don't know", "not sure") never becomes the value of a fact (place, time, people, what). It marks that item as not known (the existing unknown flags) and the chat moves on. Both layers: the assistant prompt says so, and the server drops a fact whose value is (or is taken from) such an answer. A real-AI check with «عدنة بس مامعرف» to the place question is part of the verification.
- **FR-004 Reported dates are understood**: one shared reported-date parser (used by the chat assistant's checks and by the open-case screen prefill) reads the dates people actually write: d-m-Y, d/m/Y, Y-m-d, written months in English and Arabic (Levantine/Iraqi and Egyptian names), and relative days (today, yesterday, the day before yesterday, «اليوم», «أمس», «البارحة», «أول أمس», a weekday within the last 7 days) resolved against the report's sent date. The open-case screen prefills the incident date from it (time only when stated); HR is asked for a date only when the report really has none.
- **FR-005 Unknown employee quick-add**: on the open-case screen, a person row with no match shows "Not in the employee list — add". An inline form opens on the same screen with the name prefilled from the report, the report's branch, and the fields a defense letter needs (position, department, hire date; the employee number is generated as today when the company has no own numbering). Saving creates the employee through the existing employee rules, selects it in that row, is audited, and opening continues. No page change.
- **FR-006 Report numbers**: every report gets a per-company sequential number (`violation_reports.report_number`, backfilled for existing reports in id order per company), shown as R-0001 in My reports, the reporter home, the inbox, HR home and the open-case screen title.
- **FR-007 Case numbers visible**: the open-case screen shows the case number(s) once the draft exists; case numbers use the same 0005 mono format on the case page, the case board, HR home, the incident group chips and "My cases".
- **FR-008** Translations (en + ar), Departures design, RTL, phone-friendly, behaviour inventory, help guides updated where behaviour changed; tests: drop-zone controls present, refused-type message, new-reports card and ordering, unknown-answer phrases never stored as facts (Arabic dialect and English), parser cases (each format, relative days against a fixed sent date, weekday, invalid/future), open-case prefill from text dates, quick-add creates and selects the employee and refuses another branch/company, report-number sequence and backfill, number shown on each listed screen, cross-tenant refusal for quick-add.
