# Feature Specification: Employee attendance page, dashboard, search, exports and statement

**Branch**: `505-employee-page-and-dashboard` | **Created**: 2026-10-23 | **Status**: Clarified 2026-10-23

**Input**: ROADMAP §5 spec 505. Requirements: PRD §18 (employee profile), §19 (dashboard), §20 (search and reports), §23 (scope, privacy), §25 tests 26 (agreement across profile, dashboard and reports) and 31 (language). Builds on 501–504. Overtime, compensatory entitlements, holidays, notifications and chat are later specs: their figures are not shown yet (no placeholders that look like zeros).

## Clarifications (product owner, 2026-10-23)

- **Default period**: the current month (1st → today), with quick switches (previous month, last 30 days, custom range). Every figure shows its period and the last data update.
- **Printable statement language**: HR picks Arabic or English per print; Arabic is RTL; names and source texts are never translated.
- **Q5**: attendance and discipline sit side by side on the employee page after merge-back; nothing in attendance opens or suggests a disciplinary case.

## Requirements

- **FR-001 One summary service.** `AttendanceSummary` computes every figure for an employee set + period + filters from the current derived data (503 days, 504 allocations/credits, 502 meals, data issues). The employee page, the dashboard, the Excel exports and the printable statement all use it, so the same filters always give the same numbers (PRD §25 test 26). Figures: assessed working days; present; absent (unreconciled / reconciled by leave / confirmed by HR); missing punches pending; lateness minutes; early-departure minutes; short-hours alerts; balance requiring reconciliation, reconciled minutes, remaining minutes; leave days by type and status; surplus credit created, used, available; pending days (not yet assessable); open data issues; restaurant meals.
- **FR-002 Employee page — Attendance section** (replaces the placeholder from spec 500): period picker; summary tiles (FR-001 figures); each tile opens its detail list with the same filter: daily record (status, in/out, elapsed, presence, late, early, short, balance, reconciled, remaining, leave applied with explanations), raw vs cleaned punches for a day (link to 502 punch viewer / 503 day detail), leave requests with statuses/versions, credit ledger, changes history (501), open data issues. Clear "pending" labelling for days not yet assessable; never shows an ongoing day as complete.
- **FR-003 Dashboard** (replaces the home/HR dashboard placeholder): the current position as of the latest processing run (not live): last update per source (employee list, punches, leave) and coverage quality per branch; filters period, branch, department, manager, work pattern, status; tiles for active employees, office employees assessed, absence, lateness, early departure, balance/reconciled/remaining, missing punches pending HR, leave pending approval, credits, data issues by type, restaurant meals, employees without a work pattern. Every tile opens the matching employee list (same filters) → employee page.
- **FR-004 Search**: the global search (spec 500) finds employees by name (Arabic or English, spelling-tolerant using the existing normalised `search_name`) or code, showing branch and department to tell similar names apart.
- **FR-005 Excel exports** (queued job, private file, download link, audited): employee attendance statement (one employee, period, daily rows + totals), lateness / early departure / reconciliation report (employee set), absence report, missing punches, leave and credit report, restaurant usage, data issues. Each export carries period, filters, generation time and last data update in a header block; totals equal the detail rows and the screens. Exporting never sends anything (PRD §20).
- **FR-006 Printable statement** (Browsershot PDF, HR picks ar/en): one employee, period: summary, daily table, leave and credit explanations (e.g. "Three hours were required on … Request X approved a four-hour half day; three hours were allocated, one hour of credit remains — linked by the automatic rule"), data last updated, generated by/at. No medical details beyond the leave type name.
- **FR-007 Permissions and privacy**: HR of the company and platform admins; tenant isolation on every query, export and PDF; exports and PDFs stored on the private disk and downloadable only by the requester's company HR and platform admins; audit for each export/print.
- **FR-008 Language**: English first, Arabic RTL; numbers, codes, times LTR in Arabic; exports use the requester's language for headings.
- **FR-009 Performance**: the dashboard for ~1,000 employees × one month renders from aggregated queries (no per-employee loops); summary queries use the existing current-result indexes (add any missing ones); exports for a year of one company run as queued jobs.
- **FR-010 Tests**: agreement test (same filters → identical totals on employee page, dashboard tile, export totals, PDF data); period defaults; pending days excluded from completed figures; each tile's drill-down list matches its count; search by Arabic/English/code with similar names; export content and header block; PDF renders in ar and en; permissions and isolation for pages, exports, downloads; UI inventory, translations, route sweep.

## Out of scope

Overtime, rest-day entitlements, holidays, notifications, admin chat, shift/security days (later specs); employee self-service; discipline section (Displanary merge-back).
