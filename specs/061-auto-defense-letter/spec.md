# Feature Specification: The AI writes the defense letter

**Branch**: `061-auto-defense-letter` (stacked on `060-hr-intake-polish`) | **Created**: 2026-10-21 | **Status**: Approved

**Input**: Product owner (2026-10-21): after opening a case, the defense letter step opens empty AR/EN text boxes and HR has to type the letter; "it's not easy to go to the next step"; "this is the main purpose of this project — AI must read the case and type this defense letter". Also: why does the incident case ask «اكتب وصفاً يخص هذا الموظف دون تسمية بقية أطراف الواقعة»?
Decisions (2026-10-21): the AI drafts the defense letter automatically when the case opens, so HR finds it ready; for incidents (several employees), the AI writes each employee's own description without naming the others, and HR checks it. The human confirmation gate before printing/issuing, the citation checks, the regulation comparison (CLAUDE.md §23.4) and the manual fallback (§3bb) all stay.

## Requirements
- **FR-001 Draft on open**: when a case opens (`CaseOpening::open`, `IncidentService::openDrafts`), the defense letter draft is queued automatically through the existing drafting path (`AiDrafting::request` → `DraftDocumentWithAi`), acting for the HR user who opened it. It never issues anything. With no AI key, or after the draft fails following retries, the case shows the manual path (write it / try again) as today.
- **FR-002 Regulation comparison stays a gate**: if the company has an approved internal regulation, the existing comparison runs first. When it needs HR's confirmation, drafting waits and the case's next step reads "Check the regulation comparison" (one action); confirming it continues the drafting automatically.
- **FR-003 Per-employee description (incidents)**: when an incident's cases open, the AI writes each employee's case description from the shared incident facts without naming the other employees (server check: no other member's name or token may appear; a failing proposal is dropped and HR writes it). The proposal is shown prefilled with a short explanation of why it exists ("Each letter goes to one employee and must not name the others") and one "Confirm" (or edit). Confirming saves it through the existing `IncidentService::updateCaseDescription` and queues that employee's defense letter draft automatically.
- **FR-004 Next step is obvious**: the case page's next-step panel shows the defense letter state: "Drafting the defense letter…" (progress, no action needed), "Defense letter ready — review" (primary), "Confirm this employee's description" (incidents), "Check the regulation comparison", or "Couldn't draft — write it or try again". Each opens the right screen directly.
- **FR-005 Editor with a draft**: when the editor opens on an AI draft, the page shows that it is a draft to review, the letter preview, the AR/EN texts with any AI notes (touchpoint 5) beside them, and one primary action that leads to the existing review/confirm/issue screen; "Redraft with AI" and manual editing stay available as secondary actions. An empty editor (no draft yet) never appears as two blank boxes: it shows the drafting state or the "Draft with AI / Write it myself" choice.
- **FR-006** No change to legal rules: confirmation before issue, citation checks and their overrides being logged, immutability after issue, the 15-day clock starting at issue, audit and AI logs. Translations (en + ar), Departures design, RTL, behaviour inventory, help guides ("Open a case", the defense letter guide); tests with FakeClaudeClient: opening queues exactly one draft (and none without a key), drafting failure shows the manual path, comparison gate waits then continues, incident description proposal excludes other members (and a leaking proposal is dropped), confirming the description queues the draft, next-step panel states, editor primary action leads to review, nothing is ever issued automatically.
