# Feature Specification: Open a case from a report (HR)

**Branch**:  (stacked on ) | **Created**: 2026-10-18 | **Status**: Approved

**Input**: Product owner tested "Convert to case" from the Reports inbox: it opens the old long case form, shows the reporter's "I do not know" as the place, leaves the date empty when the report gave only a date, blocks on names that are not in the employee list, hides the assistant summary and conversation, and makes HR press "Check for duplicates" by hand. Mockup approved: https://claude.ai/artifact/TXESuUTbTr3mXdd6cDspVT
Decisions (2026-10-18): one dedicated HR screen for opening a case from a report; every named person is matched to an employee record on that screen (one linked case per employee, as today); the duplicate (48 h) and conflict-of-interest checks run automatically on "Open case" and interrupt only when they find something; a case may record "time not known" when the report gave a date but no time (the system never invents a time).

## Requirements
- **FR-001 Entry**: "Convert to case" in the Reports inbox opens the new screen for that report (chat or plain-form report). Blank "New case", email drafts and editing an existing draft keep the current form unchanged.
- **FR-002 Read first**: the top of the screen shows the report summary the reporter approved (labelled as written by the assistant and approved by the reporter), or "According to the reporter: …" + description for plain-form reports. A side panel shows reporter, sent time, branch, the full conversation (when there is one), attachments and any intake answers. All text in its own language/direction (bdi/dir=auto), page labels in the interface language.
- **FR-003 People**: one row per person the reporter named (linked employees and typed names). For each, show the typed name and up to 3 candidates from  (same company + report branch, normalised Arabic search): a single exact match is preselected (HR can change it); several → HR picks one; none → "search" (inline picker) or "add a new employee" (opens the employee screen; the row re-searches on return). Opening requires every named person matched; the same employee picked twice is merged. Witnesses typed as free names stay free names (a witness need not be an employee). An alleged responsible person, if the report has one, is shown and editable (optional).
- **FR-004 Facts**: prefilled and editable, each showing the reporter's own words under it ("As reported: …"): place (location from the branch list or free text; a reporter "I do not know" is shown as unknown, never copied as the place), incident date and optional time, violation type picked from the company list (the reporter's free wording kept as the hint / free type), follow-up HR (default me), include prior record, description (from the report, editable). Validation messages name the field and the fix.
- **FR-005 Time not known**: new column  (boolean, default true, migration + ERD.md). If HR enters a date without a time, the case stores the date at 00:00 with the flag false. Every place that shows the incident time (case page, employee page, dashboards/drilldown, documents via , AI payload) shows the date only and, where text is generated, "time not stated". Deadline math is unaffected (it is anchored to the defense letter, CLAUDE.md §3).
- **FR-006 One open action**: "Open case" saves and runs the existing duplicate-candidate check (, per employee) and the existing conflict-of-interest check automatically. Nothing found → the case(s) open and HR lands on the case page. Something found → an inline panel (not a modal) lists it with "link as a duplicate report of case N" or "open as a separate case"; the choice is recorded in the audit log as today. "Save as draft" stays. No separate "Check for duplicates" button on this screen.
- **FR-007 No redundant checks**: the "Check my description" intake button is not shown for reports that came through the assistant; existing intake answers still carry over.
- **FR-008** Converting reuses  (multi-employee → linked cases); the report status and audit trail behave as today; tenant and role scoping unchanged (HR inbox visibility).
- **FR-009** Translations (en + ar), Departures design (amber only for the primary action), RTL, phone-friendly, behaviour inventory; tests: entry from inbox, summary/conversation shown, candidate matching (exact preselected, ambiguous needs a pick, none blocks with message, duplicates merged), free witnesses kept, "I do not know" never becomes the place, time-not-known stored and rendered as date only (case page + DocumentFacts), open with no duplicates opens directly, open with a duplicate shows the panel and both choices work, intake button hidden for assistant reports, cross-tenant access refused.
