# Implementation Plan: Low-Cost Legal Library Import

**Branch**: `030-low-cost-legal-import` | **Spec**: [spec.md](spec.md)

## Existing pipeline (read first)
`LawImportService` renders pages (`RenderLegalPages`), reading A per page in `ReadLegalPageText` (text layer or Tesseract OCR via `PdfPages`), reading B per page in `ReadLegalPageWithAi` (`ClaudePageReader`, model `displanery.ai.legal_reading_model`), stored on `legal_import_pages` (`text`/`text_method`, `ai_text`/`ai_status`). `UnitBuilder` splits each reading into units (`ArticleSplitter`) and `ReadingComparator` compares them (normalised by `TextNormalizer`); mismatches go to `MismatchResolver`. Platform UI: `app/Filament/Platform/Resources/LawResource/*`. AI client: `app/Ai/SdkClaudeClient.php` (anthropic-ai/sdk ^0.55 for PHP).

## Design
- **Config (FR-001):** `config/displanery.php` `ai.legal_reading_model` default `claude-sonnet-5-5`, add `ai.legal_reading_effort` default `low`; `ClaudePageReader` passes effort via `output_config.effort`.
- **Provenance (FR-006):** migration adds `legal_import_pages.ai_source` (nullable string) and `legal_import_runs.batch_id`, `reading_mode` (`now|batch`), `secondary_source_*` columns (path, sha256, uploaded_by, uploaded_at, note) and `transcription_*` columns for the uploaded transcription file (path, sha256, uploaded_by, uploaded_at, note). `text_method` gains `transcription`. Keep append-only/audit conventions.
- **Batch (FR-002):** `App\LegalLibrary\BatchPageReader` builds one batch request per pending page (same prompt/content as `ClaudePageReader`), submits via the SDK batches API, stores `batch_id`; a scheduled job `PollLegalReadingBatches` (every 5 min) retrieves status and, when ended, streams results keyed by `custom_id = page-{id}` into `ai_text`/`ai_status`, logs each in `ai_generation_logs` (input summary, model, effort, batch id, usage), then triggers the existing build step when all pages are terminal. Errors/expired → existing `failed`/`unavailable` handling so "re-read with AI" still works.
- **Transcription (FR-003):** Platform Admin action on the import run uploads a JSON `{ "pages": { "12": "…" }, "note": "…" }` (or text with `=== page 12 ===` separators). It fills reading A (`text`, `text_method = transcription`) for those pages (replacing broken text-layer/OCR output) — reading B stays API or secondary text — so the two readings remain independent. Audit-logged.
- **Secondary text (FR-004/005):** Platform Admin attaches a PDF or text; extracted with poppler (`pdftotext -layout`), cleaned by `App\LegalLibrary\WordLigatureRepair` (fixes the swapped lam-pairs; table-driven, unit tested), stored as reading B for the whole run. `UnitBuilder` gains a path where reading B is the secondary text split into articles (no page numbers) and units take page numbers from reading A. When a secondary text is attached, no API reading is requested for that run.
- **Library (FR-007):** `legal:export {--law=*}` writes `database/legal-library/<slug>.json` (law meta, jurisdictions, version, units: article_number, clause_path, text, page_number, status, version chain, source pdf sha) + `manifest.json` with sha256 per file; `legal:import` validates hashes and upserts by (law slug, version, clause_path) without touching companies' data; LawsSeeder calls it when the manifest exists. Units imported keep `verified_*` status and record `import source = library` in provenance.
- UI: run page shows source badges per reading, the batch state, and upload actions; labels via `LegalLibraryLabels`; translations en/ar.

## Tests
FakeClaudeClient for batch submit/poll/results (including errored/expired); transcription upload validation and slot filling; secondary-text comparison producing verified_auto and mismatches; ligature repair table on real lines («املادة»→«المادة», «ألحكام»→«لأحكام», no change to correct words); export → fresh DB import round trip, idempotence, hash tamper rejected; citability unchanged; tenancy (company regulations never exported); translations, behaviour inventory, Pint, full suite.

## Plan review resolutions

- **Blocker — SDK surface and testing boundary.** The installed PHP SDK exposes `Client->messages->batches->create(requests: [...])`, `retrieve($id)`, `resultsStream($id)` (an iterable stream of `MessageBatchIndividualResponse` with `customID` and a tagged `result`), and `cancel($id)`. There is no `results()` method. Each request contains `customID` and `params` in the SDK's camel-case shape. Put these calls behind an injectable batch client so tests use a fake and never contact Anthropic. `resultsStream` is available only after `processingStatus` becomes `ended`; results are not applied incrementally while processing. The completed stream can be replayed idempotently after a crash.
- **Blocker — two independent readings.** A transcription is reading A and a separately sourced typed copy is reading B. A typed copy by itself cannot verify a law. Reject identical source hashes and the official gazette as the secondary file. The page-based reading always determines article boundaries and gazette page references. Compare B by article and clause key; missing, duplicate, structurally different, or unpaired units become mismatches, never `verified_auto`. A B-only unit has no official page mapping and cannot be human-verified until an official-page reading is imported. Keep both original extractions and their source metadata. A corrected secondary copy remains a comparison aid, never official text merely because it matches.
- **Blocker — immutable verified units and export.** Export only platform statutes; include a schema version, stable law identity (`number`, `year`, `category`), law metadata and jurisdiction, source PDF SHA-256, complete unit version chains, original extractions, statuses, verification metadata and page references. Write a manifest with per-file SHA-256. Import validates the entire manifest and payload before any DB write, checks the local official PDF hash, and inserts in version order while mapping old IDs to new IDs. It must compare existing rows exactly and refuse conflicts; never update or delete verified rows, rewrite history, or mark a row verified merely on the strength of a file lacking valid integrity and provenance. Run import twice as a no-op. Seeder keeps its existing initial law creation and then imports if a manifest exists.
- **Blocker — batch reconciliation.** Mark a run `submitting` before the queued API call and submit only once automatically. A create response may be lost after the remote service accepts it; treat that uncertain outcome as unavailable and require an explicit admin retry rather than submit a duplicate automatically. Snapshot model and effort per run, and persist the batch ID before polling, so delayed results retain the actual request configuration. A completion result is accepted only when its `customID` belongs to that run and its page is still pending. Log each attempted page with image hash, model, effort, batch ID, output/usage or sanitized failure in an append-only `ai_generation_logs` row. On stream interruption retry polling and skip pages already handled. For individual error, expiry, cancellation or missing result at batch end, mark the page failed or unavailable under the existing retry policy; cancellation of a run requests remote cancellation and prevents late results from changing it. Reconciliation never dispatches immediate AI work for a batch or secondary-text run.
- **Should fix — upload races and provenance.** The import form attaches external readings while the run is queued, before any page job is dispatched. This avoids changing readings after unit construction begins. A late upload requires a new run, not an overwrite of verified units. Validate page range and nonempty UTF-8; store private paths and hashes plus uploader, timestamp, note and page-level source; audit the action without logging the uploaded text. Continue to enforce platform authorization and model tenant scope in the service, not only in Filament.
- **Should fix — batch size and costs.** The [API limit](https://platform.claude.com/docs/en/build-with-claude/batch-processing) is 100,000 requests or 256 MB per batch, with a 32 MB Messages request limit. Validate before submitting; if a run cannot fit one batch, fail visibly rather than silently splitting it or switching to costly immediate calls. The stated $1 goal is a target, not a guarantee; record actual usage where returned.
- **Should fix — reproducible export.** The repository currently has no committed verified library. Commands must not manufacture `verified_*` data; export is useful only after human/automatic verification has happened. A fresh installation has zero-cost import only when the generated JSON files have been reviewed and committed. Deployment integration must call the idempotent import at the existing seeding step; no change to old migrations or deployment scripts here.
- **Should fix — UI and translations.** Distinguish `text_layer` and `ocr` from transcription; distinguish `api` and `api_batch` from `secondary_text`. Show run batch state and uploader with no full source text in audit or AI logs. New control labels use `__()` with English and Arabic entries and only new controls enter the behaviour inventory.
